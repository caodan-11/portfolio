# 天猫订单经营分析（2020 年 2 月）

> **一句话结论**：2 月日均订单从 251 单恢复到 2,439 单（9.7 倍），流量侧不是问题；真正的损失来自退款——23.4% 的退款率吞掉 23.1% 的 GMV（57.2 万元），其中湖北退款率 71.9%、为全站 3.1 倍，问题在履约能力而非需求。

📄 **完整报告**：[天猫订单经营分析报告.pdf](./天猫订单经营分析报告.pdf)

## 业务问题

2020 年 2 月是疫情冲击最剧烈的一个月：线下关闭、线上订单集中爆发，同时跨省物流和仓储大量停摆。这个月最典型的困惑不是"有没有订单"，而是"订单来了能不能履约"。

围绕三个问题展开：

1. 订单量波动是需求端还是履约端造成的？时间结构上有什么特征？
2. 从"下单"到"实收"，GMV 在哪一环流失、流失多少？
3. 流失是否集中在特定地区或时段，能否被前置拦截？

## 数据

| 项 | 说明 |
|---|---|
| 来源 | 和鲸社区公开数据集 `tmall_order_report.csv` |
| 规模 | 28,010 条订单 × 7 字段，2020-02-01 ~ 2020-02-29，覆盖 31 个省级行政区 |
| 字段 | 订单编号、总金额、买家实际支付金额、收货地址、创建时间、付款时间、退款金额 |
| 清洗 | 列名去空格；省份名去"省/市/自治区"；付款时间为空判定为"未付款"（业务语义，非缺失值）；整日缺失只标注不插值 |

**数据质量提示**：2/8、2/16 整日无数据，2/10–2/16 仅 60 单（占 0.2%）。这是疫情停摆叠加采集中断，报告只做区间对比、不做逐日归因；剔除断档后成交率 86.0%，与全月一致。

## 指标口径

| 指标 | 定义 |
|---|---|
| 成交率 | 已付款订单数 / 创建订单数 |
| 退款率 | 退款订单数 / 已付款订单数 |
| GMV | 已付款订单的总金额（未扣退款） |
| 实收金额 | SUM(买家实际支付金额) |
| 客单价 | GMV / 已付款订单数 |

## 关键发现

1. **量：低位→断档→爆发**。上旬日均 251 单，下旬 2,439 单（9.7 倍），峰值 2/25 单日 3,416 单。含义：备货与客服要按峰值配置，而不是按均值。
2. **时间：订单压向晚间**。19–23 点占 33.9%（20–22 点单时段占 22.6%）；凌晨 0–6 点仍占 9.3%，且成交率最低（84.6%）。
3. **地区：头部高度集中**。上海 3,353 单居首（12.0%，成交率 91.3% 最高），TOP5 占 43.0%，TOP10 占 69.0%。
4. **钱：退款是最大黑洞**。全站退款率 23.4%，退款 57.2 万元，实收仅 190.2 万元；湖北 71.9%（57 单）、新疆 62.8%（43 单），分别为全站 3.1 / 2.7 倍——共同点是"无法履约"而非"不满意"。
5. **结构：高频低单价**。客单价 102.8 元、中位数仅 76 元；100 元以下占 59.9%，>500 元仅 0.7%；头部 10% 订单贡献 30.7% GMV。

## 结论与建议

| # | 建议 | 对象 | 预期影响 | 优先级 |
|---|---|---|---|---|
| 1 | 湖北、新疆下单页前置展示"预计发货时间 + 可延迟发货" | 商品/履约 | 拦截 30% 以上相关退款，约 4–5 万元 | P0 |
| 2 | 补齐退款原因字段，按原因重新归因 | 数据/客服 | 把退款定位从推断升级到原因级 | P0 |
| 3 | 排班覆盖 19–23 点；凌晨订单次日 10 点提醒付款 | 客服/运营 | 未付款 3,923 单，成交率每 +1pp 约增 30 万 GMV | P1 |
| 4 | 99 元凑单/组合装，把 76 元中位数推过包邮线 | 商品/营销 | 客单价每 +5%，月增约 12 万元 | P2 |

## 局限性

- 只有 1 个月数据且处于疫情极端期，恢复倍数不能外推到常态月份；
- 2/8、2/16 整日缺失，日趋势只能做区间对比；
- 无退款原因字段、无流量数据，退款归因是相关性推断而非因果结论；
- GMV 按订单总金额计，未扣优惠券与佣金，与财务口径可能有差异。

## 关于数据合规

使用的是**公开数据集**，不含任何公司内部数据；报告结论仅用于展示分析方法，不代表真实平台经营情况。

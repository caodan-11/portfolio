# RFM 会员价值分层（2015–2018 / 12.9 万会员）

> 用 4 年会员订单数据，按最近购买时间（R）、购买频次（F）、消费金额（M）三项打分，
> 拼成人群标签，回答「哪些客户值得优先维护」。全部计算用 Python（Pandas），结果写入 MySQL。

📄 **[完整报告](./会员价值分层分析报告.pdf)**（6 页）

---

## 数据与清洗

原始数据一份 Excel，5 个 sheet：2015 / 2016 / 2017 / 2018 / 会员等级。
前四张表字段一致（会员 ID、订单号、提交日期、订单金额），会员等级表仅作参考、未参与计算。

清洗三步：

1. **删除缺失值**——会员 ID、日期或金额为空的记录；
2. **过滤异常金额**——只保留金额大于 1 元的订单；
3. **固定观察节点**——以每年最后一天为分析截止日，并计算每笔订单距该节点的天数（计算 R 的基础）。

清洗后按「年份 + 会员」聚合，得到 **148,591 条年-会员记录**，覆盖 **129,447 名会员**。

---

## RFM 怎么算的

| 指标 | 含义 | 分档与打分 |
|---|---|---|
| **R**（Recency） | 最近一次购买距今多少天 | ≤79 天 → 3 分；80–255 天 → 2 分；256 天以上 → 1 分 |
| **F**（Frequency） | 当年购买次数 | 1 次 → 1 分；2–5 次 → 2 分；6 次以上 → 3 分 |
| **M**（Monetary） | 当年累计消费金额 | ≤69 元 → 1 分；70–1,199 元 → 2 分；1,200 元以上 → 3 分 |

三项分数拼成三位标签（如 `213` = R2 / F1 / M3），实际数据中出现 **25 种组合**。

> 分档是**手动指定的业务阈值**，不是等距或等频划分——换一套边界会得到不同的人群划分，这一点在报告的「局限」里写明了。

## 三个主要发现

**① 复购是主要增长空间**
2018 年 5.4 万名会员里，只有 **14.4%** 当年购买过两次及以上，**85.6% 只买过一次**。生意主要靠拉新撑，复购环节几乎是空的。

**② 少数人群贡献大部分销售额**
2018 年金额贡献最高的 `213` 类：**人数占 11.8%，金额占 30.9%**；而人数占比最高的 `212` 类，金额贡献只有 5.4%。

**③ 分层的价值是「排序」，不是「贴标签」**

- 金额贡献高且最近买过（如 213、313）→ 优先维护；
- 金额贡献高但很久没买 → 唤醒优先级最高；
- 只买过一次、金额也低的大多数 → 用通用活动覆盖即可，不投过多资源。

## 复现

**方式一：跑 Notebook（推荐，含写库与三维图）**

```bash
jupyter notebook code/RFM综合案例.ipynb
```

Notebook 会把结果导出到 `sale_rfm_group.xlsx` 并用 sqlalchemy 写入 MySQL（需本地有 MySQL；没有可跳过那一步）。

**方式二：只重画图**

```bash
cd code
python build_rfm_charts.py   # 依赖 ../data/sale_rfm_group.xlsx
python build_3d_chart.py     # 三维柱形图
python build_report.py       # 生成 Word 报告
```

SQL 见 [`sql/rfm_layers.sql`](./sql/rfm_layers.sql)：合并四个年度表 → 三步清洗 → 聚合 R/F/M → 三档打分 → 拼人群标签 → 统计占比。

## 说明

- 数据为公开数据集，不含任何公司内部数据；
- 「会员等级」表未参与计算，若作为分层维度可能得到更细的结论；
- 数据只覆盖 2015–2018 年，结论无法外推到当前业务。
